# *"I'm in Barcelona and I can't reach it"*

Three weeks after you got home, a message arrives: the system is not loading. Nobody can register a
patient.

You know exactly what to check. You need about four minutes with a terminal. And you cannot get in,
because the hospital's server has a private address behind the internet provider's network, and from
your flat it does not exist.

So instead you spend two days exchanging voice notes with someone on site, asking them to read out
what a screen says, guessing at the state of a machine four thousand kilometres away.

## The technical problem, briefly

Small internet providers, and almost all mobile providers, do not give each customer a public
address. Many customers share one, through a mechanism called **carrier-grade NAT**.

Outbound connections work fine — that is why browsing works. But nothing can connect *inwards*, so
there is no address you can SSH to, no port you can forward, no way to reach the server from outside.
Even if the provider did give you a public address, it would probably change.

You can check for this in five minutes, on site: compare the address the router reports on its WAN
interface against what a "what is my IP" service reports. If they differ, you are behind carrier-grade
NAT, and every plan that involves connecting inwards is dead.

**Check it in your first week. It changes the architecture.**

## The answer

A **VPN with an outbound-only connection from the hospital.** The hospital's server connects *out* to
a rented virtual server with a real public address, and holds that tunnel open. You connect to the
same rendezvous point. Now you are on the same network as the hospital, and you can work as if you
were sitting in the room.

The concrete stack: **WireGuard** for the tunnel — it is in the Linux kernel, it is small, it
reconnects silently when the address changes, and it costs almost nothing on low-powered hardware —
with a cheap VPS acting as the meeting point. AUCOOP's
[Community Network Handbook](https://aucoop.github.io/Community-Network-Handbook/3-Guide/VPN/) has
the full recipe including tooling to manage keys across many devices, and there is no reason to write
a different one here.

**Set this up during the deployment, not when you need it.** It is a two-hour job on site and an
impossible one from home.

## Two things that matter more than the tunnel

**Monitoring, so you find out before they tell you.** A server that has been down for three weeks is
a much worse problem than a server that has been down for an hour, and the difference is whether
anyone was watching. Something as simple as an uptime check that emails you is enough. Without it,
your first notification is an apologetic message from someone who assumed it was their fault.

**Credentials, handled properly.** You are about to create a lot of them: server login, database
passwords, application accounts, VPN keys, router access. Every one of them will still be in use in
three years.

!!! danger "Stop"

    Do not put credentials in the runbook. Do not put them in the shared project folder. Do not put
    them in a document that will end up in a thesis appendix or a public repository.

    This project has learned that lesson the expensive way: plaintext passwords and private keys
    scattered across eight years of project files, in a folder that syncs to the cloud and feeds
    document appendices.

    Hand credentials over separately and in person. Record *that they exist and who holds them* in
    the handover pack — not the values.

## The uncomfortable part

Remote access is genuinely necessary and it is also a trap, because it makes it easy to keep the
system alive by doing the work yourself from Barcelona.

That feels like support. It is actually the thing that prevents the hospital from ever owning the
system — and it lasts exactly as long as you personally stay interested, which is not five years.

Use remote access to help the hospital's own person fix something. Use it to diagnose, then talk them
through it. Every time you fix something silently at midnight without them knowing, the system gets
one step further from being theirs.
